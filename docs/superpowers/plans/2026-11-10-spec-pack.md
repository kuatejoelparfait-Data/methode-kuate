# Spec Pack KUATE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter à KUATE un paquet de specs structuré (K/U/A), une porte de complétude déterministe, des fichiers de tâche autoportants et une passation vers un LLM de code.

**Architecture:** La logique pure (parsing, règles de la porte, ordre des tâches, génération de fichiers, prompts) vit dans un nouveau module `packages/core/src/spec/`, testée sans réseau ni terminal. Le CLI ajoute `kuate spec` (orchestration interactive, appels IA via `resolveAiConfig`). `kuate cycle` lit l'état de porte calculé.

**Tech Stack:** TypeScript ESM, vitest, fs-extra, commander, @clack/prompts (déjà présents).

**Spec:** `docs/superpowers/specs/2026-11-10-spec-pack-design.md`

## Global Constraints

- Les documents restent dans `docs/` : `specs.md`, `backlog.md`, `architecture.md`, `data-model.md`, `contracts/*.md`, `constitution.md`, `clarifications.md`, `analysis.md`, `IMPLEMENT.md`, `stories/T-xxx.md`.
- Identifiants : `US-001`, `AC-001`, `FR-001`, `NFR-001`, `T-001` (3 chiffres minimum).
- Format story : `### US-001 — Titre` ; critère : `- AC-001 (US-001) : Étant donné …, quand …, alors …` ; tâche : bloc `### T-001 [P] — Titre` suivi de `Covers:`, `Depends:` (optionnel), `Files:`, `Done when:`.
- Marqueur d'ambiguïté : `[NEEDS CLARIFICATION: question]`.
- Sections d'architecture obligatoires : `## Stack`, `## Structure des dossiers`, `## Conventions`, `## Variables d'environnement`, `## Décisions`.
- La porte (G1–G7) et les fichiers de tâche n'utilisent **aucune IA**.
- Toute écriture qui remplace un fichier existant sauvegarde l'ancien via `backupFile` (déjà exporté par `@methode-kuate/core`).
- Les commandes `spec` qui appellent l'IA acceptent `--choose-ai`, `--provider`, `--model` (via `addAiOptions` / `resolveAiConfig`).
- `kuate spec analyze` met `process.exitCode = 1` s'il reste des erreurs.
- `kuate spec export` refuse de s'exécuter si la porte n'est pas passée, sauf `--force`.
- Textes utilisateur en français, comme le reste du CLI.

## Review Focus

- Fichiers Markdown avec fins de ligne Windows (`\r\n`) : doivent donner le même résultat que `\n` (Task 1).
- Variantes d'identifiants (`US-1`, `us-001`, `Covers:` en minuscules, point final) : normalisées, pas ignorées silencieusement (Task 1).
- Fichier absent ou vide (spec pas encore écrite) : erreur claire de porte, jamais d'exception (Task 3).
- Identifiants en double (deux `US-001`) : erreur, pas d'écrasement silencieux (Task 3).
- Marqueurs `TBD` / `TODO` dans un bloc de code ou à l'intérieur d'un mot (« mastodon ») : pas de faux positif (Task 3).
- Chemins `Files:` avec `\` ou sortant de `docs/` lors de l'écriture des documents générés : normalisés, `..` et chemins absolus refusés (Task 1 et Task 6).
